# Openyield — User stories

**Product:** [PRODUCT.md](./PRODUCT.md)


### Dataset steward

- As a steward, I want a release checklist covering licence, privacy, schema diff, and cadence, so that I do not publish incomplete dumps.
- As a steward, I want re-user tickets tied to my dataset, so that I fix the fields people actually break on.

### CDO / open-data program lead

- As a CDO, I want a ranked high-value backlog with stakeholder votes, so that we fund weather/health/geo series that unlock private innovation rather than vanity CSVs.
- As a CDO, I want a quarterly yield report of attested re-user outcomes, so that I can defend the program to OMB and legislators.

### Re-user (business analyst / data scientist)

- As a re-user, I want stable schemas with change notices, so that production pipelines do not break overnight.
- As a re-user, I want clear licence text before download, so that counsel can approve use in a product like myhealthfinder or Atlas.
- As a re-user, I want to register my project and report outcomes, so that agencies see why sustaining the series matters.

### Privacy officer

- As a privacy officer, I want linkage-risk review workflows when grain gets finer, so that open release does not enable re-identification.
- As a privacy officer, I want emergency suppression with tombstones, so that we can pull risky distributions without erasing history.

### Platform administrator

- As an administrator, I want separate tiers for open, registered, and restricted research access, so that sensitive microdata is not accidental.
- As an administrator (exception), I want to roll back a bad release and notify known re-users, so that one corrupt publish does not poison downstream models.
